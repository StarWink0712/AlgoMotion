# Trace v2 (Presets) And v3 (Generated Python)

The existing preset v2 contract below is unchanged. Generated mode uses a separate strict v3 schema, described at the end of this document. Neither mode reinterprets old exports.

## Local Library Envelope

`algomotion-library-entry` v1 is a separate persistence/backup envelope, not a new trace version. It contains a UUID, timestamps, user title, 1–6 user-selected categories and either `{kind:"draft", source}` or `{kind:"demo", bundle}`. A demo embeds the existing generated bundle v1/v2 unchanged. Drafts contain only problem text, not unconfirmed contracts or executable programs. Entries with unsupported versions/fields, invalid metadata, unsafe/invalid bundle structures or oversized content are rejected on import and reopen.

The browser stores entries and a lightweight search index atomically in IndexedDB. The library caps storage at 100 entries / 32 MiB; the per-file limit is the existing 2,300,000-byte bundle bound plus 32,768 bytes of envelope allowance. Updates/deletes compare the last-read revision timestamp inside the transaction, rejecting stale writers. Imports require confirmation and receive new identities; file IDs cannot overwrite an existing entry. Metadata does not alter runtime text, frame bindings or algorithm evidence.

Reopened evidence is always displayed as an unverified saved declaration. Opening, saving, filtering and exporting do not request a model or execute Python. Modified-input execution still uses the saved program through the existing Docker-only runner. Pending input-editor text is not part of a saved execution. Legacy `algomotion:generated:last` remains untouched until its own explicit quick-save action. Browser origins are isolated, and clearing browser data can delete the library; exported entries preserve categories and content for manual transfer.

## Contract

`runProblem(problemId, input)` either throws a readable validation error or returns a JSON-serializable `Trace`. It does not mutate the caller's input. Each frame is a deep snapshot; changing later state cannot retroactively alter earlier frames.

```ts
interface Trace {
  version: 2;
  problemId: ProblemId;
  input: unknown;
  frames: Frame[];
  result: unknown;
}
```

Each `Frame` contains:

| Field | Meaning |
| --- | --- |
| `step` | Contiguous zero-based frame number. |
| `location` | Language-independent semantic step, e.g. `dequeue`, `transition`, or `return`. |
| `action`, `explanation` | Human-readable description of the just-recorded operation. |
| `values` | Array elements or graph node values. Node ID is its index, not its value. |
| `elementIds` | Optional stable element identities for in-place array swaps; unlike values, duplicate elements never share an ID. |
| `active` | Currently involved indices / node IDs. |
| `settled` | Confirmed indices / processed node IDs, interpreted by the preset. |
| `pointers` | Named indices / node IDs, or null. An array pointer may equal length after advancing past the end. |
| `variables` | Small JSON-serializable watch values. |
| `table` | Optional `[key, value]` entries for the algorithm's hash map. |
| `window` | Optional inclusive current interval, not necessarily a globally optimal interval. Search uses pending elements; half-open algorithm bounds `[left,right)` are stored as `[left,right-1]`, with an inverted/empty interval when no elements remain. Jump Game uses `[0,min(farthest,n-1)]` for reachable positions, not a chosen path. |
| `links` | Optional directed `[fromId, toId]` edges; absent outgoing link means null for a list. |
| `edgeLabels` | Optional `"from-to": "L" or "R"` labels for binary tree child semantics. |
| `levels` | Completed BFS output levels. |
| `queue` | Optional waiting BFS node IDs, in FIFO order. `variables.queue` still contains their values for the watch panel. |
| `path` | Optional current LIS chain, represented by original input indices. Derived from predecessor choices made by the DP runner. |
| `bestPath` | Optional best LIS chain, best left/right water-container boundary pair, or the stock preset's best buy/sell day IDs (empty when no profitable trade). |
| `dp` | Optional DP state aligned with `values`; unreachable is the string `∞`, not numeric Infinity. |
| `result` | Present only in the final frame, equal to `trace.result`. |

## Playback

Rendering a frame is independent of playback direction. Seeking changes an index, not the algorithm's state. Input submission calculates a new trace, pauses the player and resets the cursor. Invalid input keeps the last successful trace and displays an error.

The desktop preset workspace also displays a separate final-output card beside the input editor. It reads `trace.result` and `trace.input` from the last successful execution, independent of the playback cursor; it intentionally reveals the final answer immediately, without inserting future values into the current frame. Pending edits and failed inputs explicitly retain/label the previous output. Value comparison ignores JSON whitespace and object-key order, but preserves array order and scalar types. The algorithm's key idea now sits below the reference code, with language compatibility notes folded separately. This does not execute the displayed Java/Go/Python references or change generated-mode evidence/display rules.

The visual layer derives teaching formulas and dependency arrows from the selected snapshot and its algorithmic predecessor. These annotations are distinct from execution state. Water at completion explicitly replays the saved best pair rather than implying the terminal collapsed pointers enclose the maximum area. Retired linked-list edges are labeled as disconnected; they are not counted as live links.

Stable element/node IDs animate between adjacent frames with the Web Animations API. Non-adjacent seeks snap positions and cancel stale movement. Drawing pulses are finite, scaled to playback speed, and disabled for `prefers-reduced-motion`; no background animation loop is used. Pausing stops automatic stepping; the current short visual transition may finish. Input changes remount the scene so old identities cannot animate into a new input. Snapshot correctness does not depend on animation completion.

Snapshotting uses `structuredClone`, then normalizes numeric negative zero to positive zero in the cloned input, frames and return value. These integer teaching contracts do not distinguish two kinds of zero; normalization makes the in-memory trace equal to its JSON export without modifying the caller's input or live algorithm state. Text such as `"-0"` is preserved. There are no function references, DOM nodes, Dates, undefined properties or cyclic values in the resulting trace. The engine caps traces at 1,000 frames, and each preset has stricter input limits.

## Correctness and limits

The renderer displays deterministic execution state, but a deterministic algorithm can still contain bugs. Unit tests, independent brute-force / BFS reference comparisons and browser tests reduce that risk; they do not prove universal correctness or establish that an AI-selected template matches the user's intent.

The code pane offers maintained, trusted Java, Go and Python reference implementations, not arbitrary editable code. Each snippet contains authoring-only `// @trace location` or `# @trace location` markers; the parser strips them and derives a one-based `locations` map. A frame's semantic `location` selects the appropriate line for the selected language. Tests require all three implementations to expose the same semantic locations and cover all emitted locations.

Changing language never reruns the algorithm or changes the playback cursor. A frame can summarize several equivalent statements, such as Java's three-assignment swap or Go's queue read followed by head increment. It is not a native-language debugger. Coin Change uses an integer sentinel in Java/Go and infinity in Python; the visualization consistently displays unreachable states as `∞`, with this difference stated beside the code.

Version 2 replaces version 1's JavaScript-specific `line` field with `location`; older exported files retain version 1 and are not rewritten. Trace import is not supported in either version. The browser still runs the trusted TypeScript engine; choosing a reference language does not execute that language in the browser.

Tree input uses compact breadth-first notation, e.g. `[1, null, 2, 3]` gives root 1, right child 2 and 2's left child 3. It is not heap-index storage. Reject disconnected values, a non-null node after an empty root and trees deeper than five levels. Graph layout prioritizes non-overlapping nodes; `L` and `R` labels retain child orientation for sparse trees.

Array/input limits are for readable teaching demonstrations, not the full original online judge constraints. Two Sum returns the first found pair or `[]`; Climbing Stairs defines `n=0` as one empty path; string lengths count Unicode code points, not grapheme clusters.

The search/greedy batch reuses Trace v2 without new frame fields. Search Insert requires strictly increasing input, Search Range permits sorted duplicates, and Rotated Search requires a rotation of distinct ascending values; invalid order is rejected rather than silently sorted. Empty search inputs return 0, [-1,-1] and -1 respectively. Stock accepts empty input with profit 0 and requires a strictly earlier buy day for a positive trade. Jump Game requires a nonempty nonnegative array and returns true for a singleton. All five accept at most 24 elements. Input validation/snapshot costs are separate from the displayed algorithm complexity. Search keeps exclusive endpoint pointers at n visible as an extra end gap; overlapping pointers remain inside the scene. New range bands animate only forward-adjacent changes and cancel old movement on rewind/seeks. See [HOT100.md](HOT100.md) for incremental coverage.

### Final String, Cancellation And Functional-Graph Presets

Batch 11 completes the planned catalog with 5, 1143, 72, 136, 169 and 287 without changing Trace v2. `EssentialView` internal v1 describes palindrome/XOR/vote teaching state: the current equation, this-step pair, pending input IDs, candidate/count, XOR before/operand/after values, and best contiguous palindrome IDs/text. Longest Palindrome expands odd/even centers, stops at the first mismatch and prefers the leftmost start on ties. Its current range can be a rejected candidate; the separate best text is always a previously proven palindrome. XOR shows 8-bit two's-complement values, but only after reading an actual input; its pending IDs are unmatched occurrences in the consumed prefix, not future answers. Majority voting stores unmatched same-candidate IDs and explicitly distinguishes vote balance from frequency. Paired IDs are processed, not selected as final answers; completion highlights the pending survivor IDs.

`DPGreedyView` v1 gains backward-compatible optional `axes`, `registerPath` and `alignment` fields. Axes label source/target prefix lengths and corresponding characters, including the empty prefix. LCS/Edit preallocate null cells, record boundary values and fill in row order; each dependency stores an actually computed source. LCS uses diagonal+1 for a match or max(up,left), choosing up on ties. Edit uses diagonal+0 for a match or min(replace,delete,insert)+1. Backtracking records reverse state paths and prepends recovered alignment columns. Partial alignments are labeled recovered suffixes, never full scripts. At completion LCS matched columns form one optimum subsequence; Edit columns consume the full source and produce the full target, with keep costing zero and insert/delete/replace costing one. The numeric result remains length/distance rather than a new output object. The reference edit snippets retain alignment front-insertion, and their complexity label includes its overhead.

`LinkedListView` v1 gains optional `edgeMode: "array-index"` and `traversed` edges. In duplicate-number mode, nodes are input indices and every static edge is i→nums[i]. Traversed edges highlight actual reads, including the fast pointer's intermediate hop, not rewiring. Phase one meets inside the cycle; phase two resets finder to 0 and moves both one step to the entrance. Return is the entrance index d, not a read of nums[d]. The array is never changed. Ordinary linked-list frames omit these fields and keep existing semantics.

Bounds: palindrome≤16 lowercase ASCII characters; LCS/Edit inputs≤8 each; single-number arrays 1–23 values in [-128,127], exactly one singleton and all others paired; majority arrays 1–24 bounded integers with a strict majority; duplicate arrays 2–13 values in [1,length−1] with exactly one repeated value (multiplicity may exceed two). Invalid assumptions are rejected, not silently repaired. Prefix DP scrolls internally with labeled axes; array, graph and pending-token movement use existing motion primitives and forward-adjacent guards. These additions have type checks and authored tests, but runtime/native/browser acceptance is deferred to the consolidated phase.

### Greedy Frontiers And DP State Dependencies

Batch 10 retains Trace v2 and adds a trusted preset-only `DPGreedyView` (internal version 1) at `variables.view`, rendered by `StateDPScene`. Input elements/characters/grid costs/square choices remain in `frame.values`. DP register IDs are not input indices: `dN` denotes a prefix/amount/target sum, `pR-C` a Pascal cell, `hiN`/`loN` the product extrema ending at N, and `gR-C` a grid state. Source IDs `sN` explicitly reference input positions. Each register records its row, column, label, current scalar value and optional update epoch. Null means not computed, numeric 0/1 denotes false/true reachability, and the string `∞` is an uninitialized square-count bound (native references use n+1), never a nonfinite JSON number.

Dependencies carry source/target IDs, the actual source value at this transition, eligibility, selection and optional source epoch. A legal candidate that did not improve a result is distinct from an ineligible edge. DP candidates, active register, original-input witnesses and complementary witnesses, segment boundaries, reachability ranges, last-character positions, dictionary and computed segment lengths are snapshot annotations. `witnessMode` distinguishes sums, products and paths. Dependencies and candidate cards are cleared between operations; input highlights are cleared before a new amount/prefix. Finishing clears transient input highlights/edges, but preserves computed state and witnesses. No final answer is inserted into earlier snapshots.

Jump Game II collects a whole reachable layer before incrementing jumps, returning -1 if its frontier cannot advance and 0 for a singleton. Its bands denote all reachable positions, not a chosen route. Partition Labels first records last occurrences then commits the earliest legal cuts. Pascal fills only edges or cells with two computed parents. House Robber compares skip/take from valid nonadjacent prefixes. Perfect Squares stores improving predecessors and reconstructs a decomposition that may use the same square repeatedly. Word Break requires both a reachable prefix and a dictionary suffix; the empty prefix is reachable. Maximum Product computes both extrema from old values, stores input-index intervals and normalizes arithmetic negative zero to integer zero.

Equal Subset uses descending 0/1-knapsack updates with the source's prior epoch strictly smaller than the current item round; distinct positions remain distinct even if their values match. A successful witness and its complement cover all input indices. Unique Paths sums disjoint up/left path counts and has no single-path witness. Minimum Path Sum adds the current cost to the cheaper valid predecessor, including endpoints; upper-predecessor ties select one representative optimal route without claiming uniqueness. Only right/down moves are allowed for these two grid presets.

Limits: jumps≤24 values in [0,24], label string≤24 lowercase ASCII characters, Pascal≤10 rows, houses≤16 values in [0,100], squares n≤40, word string≤14 and dictionary≤8 unique nonempty lowercase words of length≤14, products 1–12 values in [-5,5], subset 1–12 positive integers≤30 and total≤60, grids 1–6 rows/columns and costs [0,100]. Complexity labels describe the displayed core reference algorithm, excluding immutable trace snapshots, history boards and witness-copying annotations. Long state lines wrap into six columns; wider product/Pascal/grid boards scroll internally. The focus/flow primitives animate only forward-adjacent playback; rewind/seeks cancel movement and restore state. Behavioral, native-language and desktop layout/animation acceptance remains deferred.

### Ordering, Partition, Heap And Trie Presets

Batch 9 retains Trace v2 and adds two trusted preset-only view types, both internal version 1. No generated trace/schema/configuration change is involved. `OrderingView` represents array, matrix or two-array partition mode, dimensions, allowed matrix indices, this-step swaps, equation/phase, named lanes, optional cuts and cut search range, four boundary values and actual median element IDs. Matrix/array elements use `frame.elementIds`; IDs survive swaps even when values are equal. A matrix slot is row*cols+column, distinct from the element identity that moves between slots.

First Missing Positive repeatedly swaps valid x into x−1, stopping on duplicates and out-of-range values, then scans the first missing home. Rotate Image transposes then reverses rows. The matrix scene animates the same elements between positions with space for arc travel. Search Matrix I accepts globally strictly increasing row-major order and performs virtual 1D binary search; Matrix II accepts nondecreasing rows/columns (including duplicates), starting at top-right and excluding entire rows or columns. Excluded cells remain visible but are not candidates. Rotated Minimum requires a nonempty distinct rotation and retains mid on the smaller-side branch; it does not display an irrelevant n-th insertion gap.

Median of Two Sorted Arrays always partitions the shorter array, including cuts at 0 and length. The left side contains ceil(total/2) elements. Missing boundary values are encoded as null in the view and interpreted only for display as negative infinity on the left / positive infinity on the right, never actual array elements or nonfinite JSON numbers. Cross comparisons show their actual ≤ or > relationship rather than asserting a false inequality. The final one/two median IDs refer only to real elements. One input may be empty; both may not be empty.

`StructuresView` contains real heap slot-ID arrays with min/max type and names, node priorities, original source and read cursor, optional held/extracted node ID, accumulated frequency entries, Trie nodes, active prefix path, completed outputs, current operation/equation, a traversed/created connection and optional computed median. Heap values reside in the finite identity registry `frame.values`. Historical extracted nodes in that registry are not live heap members; only current slots plus an optional held node are drawn. Heap push/pop/compare/swap/ready locations represent actual binary-heap operations. Insertion/removal may temporarily violate heap order until ready; two-heap size balance is required after addNum completes, not after each intermediate operation. A held node moves between heaps without changing its identity/value. The source strip is labeled original input, not active heap contents. Only completed queries produce median output; no future medians are synthesized.

Kth Largest counts duplicates separately and retains k items after eviction. Top K Frequent counts each distinct value, with lower frequency weaker and larger value weaker on frequency ties; extraction then reversal produces frequency-descending, value-ascending output. Median Finder maintains a lower max-heap and upper min-heap, sizes equal or lower one larger, with all lower values ≤ all upper values. All three reference languages include the manual heap operations corresponding to the semantic steps, not opaque sorting replacements.

Trie creates one root and only allocates missing character edges during insert. Queries never allocate nodes. Each node has an ID, parent, character, prefix and terminal flag; complete-word queries require terminal while prefix queries only require reaching the node. Empty prefix exists even in a fresh trie, while the empty word must be inserted to mark the root. Layout uses finite nodes grouped by depth and stable identity, not the entire potential alphabet tree. New queries preserve prior nodes and flags. Unsupported operations, uppercase/non-ASCII strings and excessive insert characters are rejected.

Limits: numeric values [-10000,10000], arrays≤24, matrices≤6×6, combined median arrays 1–24 elements, k from 1 through input length or distinct-value count as applicable. Trie≤12 operations, word length≤5, total insert characters≤24; stream≤24 operations and≤16 addNum calls, with empty-stream findMedian rejected. Array/matrix/heap layout scrolls internally and uses forward-adjacent movement only; rewind/seeks snap/cancel motion. Core complexity labels exclude trace snapshots and display registries. Runtime, native-language, motion and actual layout validation remain deferred as recorded in VALIDATION.

### Advanced Trees, Merge Lists, LRU And Backtracking

Batch 7 retains Trace v2 and preset-only `variables.view` version 1. It does not change generated Trace v3, execute displayed reference languages, or introduce a model/container dependency for presets. Existing tree/list view additions are optional: `sourceLabel`, a second input `sequence` with consumed cursor, current-branch `frequencies`, matched downward paths in `matches`, target node IDs in `targets`, and list divide/merge `work` labels.

Preorder/inorder construction rejects duplicate values, inconsistent traversals and depth over five before tracing. Only allocated nodes appear in frames. Path Sum III counts nonempty downward paths using ancestor-prefix frequencies; lookup precedes insertion, and exit removes only the current prefix occurrence. Its highlighted active root-to-current path and per-lookup matched suffix paths are different from a final global witness. LCA inputs p/q are IDs in compact nonnull BFS order, not values or indices in the nullable input array; both must exist, p=q is allowed, and the UI result is `{id,value}` for the returned original node. Maximum Path Sum requires a nonempty tree, stores a connected best witness and distinguishes the single-side return from the two-side candidate.

Sort List performs recursive merge sort on actual next pointers (O(log n) core stack, not the constant-space follow-up). Merge K Lists uses balanced divide/merge. Both choose the left node on ties and retain all original identities and values. `view.output` is the selected prefix of the current merge, not the unselected tail still reachable through a chosen node's old next. Starting another subproblem clears this partial-output annotation. Origin heads denote original objects, not independent remaining lists after rewiring. Inputs are limited to 12 nodes for sorting, or at most four sorted lists / 16 total nodes for K-way merging.

The `cache` renderer uses `CacheView` v1: capacity, current MRU-to-LRU `order`, live `entries` with stable id/key/value/prev/next, hash `lookup` pairs, already-completed `outputs`, current `operation` and index, touched ID and optional just-evicted record. The executor maintains a Map and real doubly-linked nodes. The renderer does not infer cache membership from historical allocations in `frame.values`. Touch updates both neighbor links atomically; insert may temporarily have capacity+1 live entries, immediately followed by eviction. Evicted records are annotations, not live nodes. put yields null; get miss yields -1 without changing order. Capacity is 1–6 and at most 24 operations are accepted.

The `backtracking` renderer uses `SearchView` v1: a `path` of unique choice-token keys and source indices, collected `answers`, next-call `available` candidate indices, remaining sum (null when inapplicable), the current candidate and an optional just-removed choice. Answers are runtime copies, never future completions. Choose arrows point from a source to the new choice; undo removes the actual last choice and restores the caller's remaining sum and available set. Repeated candidate usage has different token identities. Forward-adjacent moves/flows animate; rewind/seeks snap to the selected snapshot and cancel prior motion. Candidate/path tokens wrap; result collections have bounded internal scroll areas.

Permutations accepts at most five distinct integers; Subsets accepts at most seven. Both define empty input as one empty answer. Combination Sum accepts at most five distinct positive integers (1–100) and target 0–10, sorts a copy, allows candidate reuse, and defines target=0 as one empty combination. These teaching bounds are intentionally smaller than online judge limits to stay within the existing 1000-frame cap. Runtime behavior, Java/Go/Python execution and desktop acceptance for this batch remain deferred; type checking is not proof of those claims.

Construction displays only allocated nodes; disconnected partial subtrees are attached when recursive calls actually return.

Subtree swaps preserve IDs and update child-side labels and layout slots. Flattening uses predecessor rewiring, not a prerecorded preorder list. It temporarily can have two incoming links to a subtree between bridge and lift steps; layout uses the finite saved slots rather than recursively traversing that intermediate graph. Committed nodes move to a bounded horizontal row, avoiding exponential-width coordinates for the final chain. At completion every left pointer is null, the right chain is in preorder and node identity/value are preserved. References additionally return the root for the display adapter; the platform void signature may omit that return. Inversion/construction outputs use canonical compact level order with trailing nulls removed; flattening outputs right-chain values.

Authored native adapters independently check inversion swaps on the original objects and flattening's exact original preorder identities, null left pointers and chain termination. Runtime, native-language and browser checks for this batch, including the shared-parser regression, remain deferred as recorded in VALIDATION. Core complexity labels exclude tracing, layout registries and stored witnesses. Generated-mode schemas, sandbox and configuration are unchanged.

### Linked-List Presets

The fifth batch keeps Trace v2 and adds the trusted `linked-lab` renderer without changing the existing reverse-list or tree scene. Its preset-only `variables.view` version 1 records stable layout `lanes`, named `heads`, `dummy` and `detached` node IDs, committed `output` IDs with `outputLabel`, `randomLinks`, original/copy identity pairs in `copies`, explicitly `changed`/`retired` next edges and the current `group`. Live next edges remain in `frame.links`, and each node ID is an index into `frame.values`, including real auxiliary sentinel nodes. Sentinel values are not returned as input values. Detached nodes remain objects with their actual remaining next pointer; the drawing does not claim that bypassing a node destroys it.

Lanes identify node origin, not necessarily disjoint live components. Layout visits the finite lane registry rather than recursively following next, so cycles, self-loops, shared tails and transient rewiring states remain representable. Input IDs do not move just because connections change. Pointer badges and newly established edges animate on forward-adjacent steps; rewind/seeks cancel movement. A retired edge is an operation annotation, not a live link. Random pointers and original-to-copy mappings have separate styles; the latter is explicitly labeled as a mapping, never included in next/random edges. The result strip shows the committed prefix during construction and the complete ordered result at completion, not the entire temporarily reachable suffix after every append.

Intersection input is `{prefixA, prefixB, shared}`: the shared tail is allocated once and both prefixes connect to it; equal values in distinct prefixes do not imply intersection. Its result is `{indexA,indexB,value}` or null, while references return actual node objects and native adapters serialize by identity. Cycle inputs use `{values,pos}`, where pos=-1 means no cycle and otherwise the last next points to that input index. The pos field constructs the graph only; both algorithms execute pointer traversal. Cycle II returns the detected node's input index or null. Read-only cycle/intersection paths never rewire their inputs.

Palindrome uses a real half-list reversal and comparison, then restores the original next links even after a mismatch. Merge reuses nodes of two independent nondecreasing inputs, choosing A first on equal values. Add Two Numbers allocates a separate reversed-digit result and preserves both inputs; operands have 1–8 digits, no redundant high zero, and zero is `[0]`. It never converts whole operands to a fixed-width integer. Removal changes the predecessor next, pair swaps change three connections, and k-group reversal first proves a full group exists. An incomplete final group remains unchanged, including k greater than the list length.

Random-copy input is `{nodes:[[value,randomIndexOrNull],...]}`, with implicit next-to-next-item links. Two passes allocate distinct nodes and then wire only copied nodes to one another. Random self/cross links are allowed; targets outside the input are rejected. Its serialized result has the same pair format, which alone does not prove a deep copy: the authored engine/native tests separately inspect identity separation, topology and unchanged originals.

General lists allow at most 12 values in [-10000,10000]; intersection has at most 18 total nodes, merge at most 18 input nodes, random-copy at most 10 originals. Removal requires a nonempty input and 1 ≤ n ≤ length; k is an integer in [1,12]. The largest addition demonstration allocates at most 26 nodes including its sentinel. These are teaching bounds, not platform maximums. Trace snapshots and display registries add storage/time beyond the stated core-algorithm complexity. All fifth-batch runtime, native-language and browser acceptance remains deferred; no generated-mode protocol or sandbox changes are involved.

### Stack And Window Presets

The fourth batch keeps Trace v2 and introduces the trusted `stack-window` renderer. Its preset-only `variables.view` version 1 stores `structure` (stack/deque/frequency), stable-ID `entries`, partial `output` with `outputLabel`, and optional operation `transfer`, input-index `relation`, `frequencies`, per-column `water`, candidate `rectangle`, `bestRectangle`, `bestRange` and `text`. It does not extend generated-mode schemas, evaluate code, or enable preset-trace imports.

Entry IDs are input/operation positions rather than values; the longest-valid-parentheses sentinel has ID −1 and is never treated as an input character. A transfer records direction, entry and structure slot. Removed entries are displayed separately from actual membership. Forward-adjacent navigation can animate transfers and water growth; rewind/non-adjacent seeks cancel motion and restore the selected snapshot. Input lanes scroll internally, while stack/deque slots wrap at the measured viewport width. Truncated stack-prefix labels retain their full value in an SVG title.

Daily Temperatures exposes unknown answer slots as null until their warmer day is found; remaining slots become 0 only after scanning completes. This is a visualization of whether an answer is established, not a claim that the displayed reference's zero-initialized answer buffer contains null. Min Stack uses null as an actual return value for push/pop; the two meanings are labeled separately. Its JSON protocol is `{operations:[{op:"push",value:integer},{op:"getMin"},...]}` with an initially empty stack, no constructor command and at most 24 operations. The references expose a MinStack class plus a runOperations adapter; invalid empty-stack operations are rejected before tracing.

Histogram rectangles record inclusive columns, height and actual area; an end sentinel flushes the stack without inserting a fake negative-height input column. Equal heights remain in the stack, and each candidate is evaluated before recording the best. Rainwater records only newly enclosed layers, accumulated per column; unbounded pops clear old wall arrows. Current windows, last measured rectangles and historic best ranges are separate state, not interchangeable annotations.

Numeric inputs are limited to 24 elements (nonnegative heights at most 100, temperatures −100 to 100, other values −10000 to 10000). Sliding-window maximum requires 1 ≤ k ≤ n and a nonempty array. It retains the newer index for equal candidates. Bracket strings have at most 32 characters. The two frequency-window presets intentionally accept ASCII letters only, case-sensitive, with source length at most 32 and target length at most 12; anagram targets must be nonempty. Minimum Window returns the leftmost minimum-length answer on ties, and returns an empty string for an empty target or no cover.

Decode String accepts at most 32 encoded characters, ASCII letters, positive counts 1–20 and at most six bracket levels. A length-only grammar pass rejects empty brackets, dangling counts, mismatched brackets and expansions over 120 characters before allocating expanded output. References assume this validated input. The documented O(n × L) time is a conservative bound accounting for repeated string construction, not an unqualified O(n) claim; trace/display overhead is additional. All fourth-batch behavioral and visual acceptance remains deferred as recorded in VALIDATION.

### Array Transformations

The array-transformation batch also uses Trace v2. Swaps and sorting preserve `elementIds` even when values repeat. Color partition boundaries are updated atomically with each placement, so a recorded frame never labels a displaced 0 as belonging to the known 1-region. Rotation uses three explicitly named reversal phases; Next Permutation preserves a nonincreasing suffix until the pivot exchange, then reverses it. Their `window` is the selected subrange, not necessarily the current two-pointer span.

For 3Sum, `variables.view` version 1 contains only discovered `triplets`. For Merge Intervals, it contains input `items: {id,start,end}[]` and `merged: {id,start,end,members:number[]}[]`; members refer to original interval IDs, while frame active IDs index the current ordered input rows. Coordinates are closed intervals, touching endpoints merge and single points remain visible as point glyphs. Numeric widths otherwise use a shared input-derived axis. `variables.view` is reserved for these bounded preset display payloads and omitted from the generic watch row. These additions do not change generated-mode schemas or allow preset imports.

3Sum allows up to 16 integers in [-10000,10000], returns ascending value triples in numeric lexicographic order, and never repeats a value triple. Sort Colors allows up to 24 values in {0,1,2}; its partition is not a stable sort. Rotate Array allows up to 24 bounded integers and right rotation by k in [0,1000000000], with empty input handled before modulo. Next Permutation accepts up to 24 bounded integers with duplicates, wrapping to ascending order when maximal. Merge Intervals accepts up to 12 pairs in [-100,100] with start <= end. Runtime, native-reference and visual verification of this batch remain deferred; see HOT100.md.

The array/hash batch still emits Trace v2. Its optional preset-local `variables.view` object has `version: 1` and bounded `groups: {key,indices}[]`, `prefix`, `suffix` or `matches` arrays as applicable. Group indices are stable original word IDs, preserving empty/duplicate words. Product rows use null for not-yet-recorded prefix/suffix values; `dp` contains the actual working output, not precomputed final answers. Prefix-sum positions range from 0 through n (unlike element IDs); only earlier prefix positions may match the current end, and initial frequency {0:1} includes the empty prefix but never an empty subarray. These fields are rendered in dedicated views instead of repeated in the watch list. No generated bundle is interpreted as a preset view.

Longest Consecutive uses deduplicated values in first-occurrence order; its `path`/`bestPath` IDs address that set, not original positions. Chain values differ by one and may move left or right on the input-order canvas. Product inputs are bounded to 12 integers in [-5,5], keeping all prefix/suffix intermediates within signed 32-bit range; empty input returns [], singleton input returns [1]. Anagrams accept at most 12 lowercase ASCII words of at most 8 letters, with first-seen group order and original order within groups. Longest Consecutive and Subarray Sum accept up to 24 integers in [-10000,10000]. These are implementation contracts; the second batch's runtime/browser verification is deferred, as recorded in HOT100.md.

## Trace v3: Generated Python

```ts
interface GeneratedTrace {
  version: 3;
  origin: 'python-runtime';
  input: unknown;
  frames: GeneratedFrame[];
  result: unknown;
}
```

`GeneratedFrame` contains `step`, actual Python caller `line`, `action`, `explanation`, `grid`, `active`, `visited`, `blocked`, `queue`, `path`, `dp`, `dependencies` and `variables`. Dependencies are `{from,to,label,chosen}`; IDs are row-major positions, not values. See `src/engine/generated.ts` for complete Zod schemas and [GENERATION.md](GENERATION.md) for the Python SDK and limits.

The controlled SDK snapshots at actual `trace.snapshot()` calls. The model API returns Python only, not an animation dataset. Inputs and code enter restricted containers over stdin; no host Python fallback. Transport/state are untrusted and revalidated outside the container. Runtime origin is not tamper-proof instrumentation or an algorithm correctness proof.

Playback indexes immutable snapshots, independent of direction. Seeking renders the selected grid, DP, queue, path, watches and source line. Forward-adjacent dependency animation is finite; non-adjacent seeks remove old arrows/particles, and MovingGroup cancels prior motion. Input/program replacement remounts the scene. Reduced motion keeps complete state without animations.

Result bundles have their own `format: 'algomotion-generated'` and contain contract, actual Python source, v3 trace and separate evidence levels. Bundle v1 has no presentation; bundle v2 requires `program.presentation: SceneSpec` v1. Neither changes Trace v3 or preset Trace v2. Import checks bytes, version, fields, dimensions, IDs, step order, finite values, source lines, input contract and all presentation bindings against every frame. It renders only text/SVG, never imported code. Imported evidence is displayed as unverified file claims until a fresh Docker run/check. Presets retain original Java/Go/Python references; generated mode exposes only the actual executed Python.

## SceneSpec v1

This is a bounded, data-only presentation language, not HTML/JavaScript, a template engine or executable expressions. A separate real model request sees the confirmed contract and sampled actual snapshots and returns only this description. The host validates it before the trusted React/SVG components render it.

```json
{
  "version": 1,
  "title": "运行状态与路径",
  "description": "说明为模型建议，不是验证证据。",
  "theme": "mint",
  "layout": "split",
  "panels": [
    { "id": "board", "kind": "grid", "title": "网格", "source": "grid" },
    { "id": "queue", "kind": "queue", "title": "待处理", "source": "queue" },
    { "id": "answer", "kind": "result", "title": "返回值", "source": "result" }
  ]
}
```

- At most six panels, unique ASCII IDs. First panel is grid/sequence/graph bound to recorded frame state, not static input or final output; at most one grid. Themes: sky/mint/sand/rose. Layout: split/stacked, responsive on mobile.
- Allowed bindings: `grid`, `dp`, `queue`, `path`, `dependencies`, `variables`, `input`, `result`, or up to four own-property keys under variables/input/result. No prototype keys, bracket expressions, scripts, event handlers, CSS or URLs.
- Grid binds only `grid`, reusing cell focus, visited/obstacle markers, DP overlays, candidate/chosen arrows and path edges.
- Sequence flattens scalar arrays/matrices, with tiles or bars. Bars must be numeric in every frame. Queue/stack/path require flat scalar arrays; coordinate pairs are rejected, not silently flattened. Stack reverses the bound bottom-to-top array for display. Core queue/path IDs display row/column coordinates.
- Graph uses `source: grid, edges: dependencies` for cell-ID nodes; custom graphs bind arrays of `{id,label}` nodes and `{from,to,label?,chosen?}` edges, commonly `variables.nodes/edges`. At most 48 unique nodes and 48 valid-reference edges. Layout is circle/rows; it is not an arbitrary graph drawing language.
- Values/result panels display JSON from their bindings. All `result` bindings are hidden before the last frame, regardless of panel kind. A state variable may be absent in earlier frames, shown as not recorded; a binding that never exists is invalid.
- SceneSpec `title`, `description` and panel `title` remain untrusted archival metadata for compatibility. The default player does **not** use them as headings, graph accessibility labels or explanations. It derives trusted panel labels and a current-frame summary (step, grid dimensions, sequence length or graph counts) from runtime state. Original AI prose/JSON is mounted only after opening the explicitly marked static/spoiler inspector; changing input/program closes that inspector. This prevents old SceneSpec answers, dimensions and direction claims from masquerading as current state. Runtime-recorded action/explanation text remains untrusted instrumentation, not a proof of semantic accuracy.
- Data compatibility is checked across every frame of the main execution, model example executions and applicable independent boundary executions **before design completion**. Both newly generated and reused plans use that corpus. The model sees a bounded capacity summary, including maximum grid cells; a grid-backed graph cannot pass if an executed case has more than 48 cells. Failed plans are not silently truncated or converted into another renderer.

Normal input reruns reuse both Python and SceneSpec without model calls. If any checked execution is incompatible, even when the current input fits, the job fails explicitly and preserves a readable raw v1 diagnostic bundle. Errors identify the case, panel index, frame and capacity/type/reference issue without echoing arbitrary binding names or data. Evidence details report the number of executions checked. This covers finite executed cases, not every possible input in a contract; generic problems without independent verifiers have current/sample coverage only. The user may explicitly request a new design. Playback still indexes actual snapshots; it does not regenerate algorithm steps. Non-adjacent/backward bar seeks snap immediately rather than interpolating obsolete values. Reduced-motion settings disable decorative movement.
