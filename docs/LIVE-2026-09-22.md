# Real Model Acceptance: 2026-09-22

## Conclusion

Real DeepSeek API -> generated Python -> restricted Docker -> runtime trace -> browser playback was exercised, not mocked. Both tasks produced programs with correct results on small inputs after explicit contract review. **Overall acceptance is not fully passed:** model contract quality, trace protocol adherence, teaching state and in-range large inputs still have failures. Successful numeric results must not be conflated with a complete, accurate demonstration.

Provider/model: DeepSeek / `deepseek-flash`, JSON Object, `max_tokens`, thinking disabled, configured output budget 8192. The existing local API at `127.0.0.1:5173` held the user's session-only key. Tests used that API, never retrieved or copied the key, never restarted the service and never persisted credentials. Docker Desktop was installed but stopped; it was launched without reinstalling or changing system security settings.

Exactly **8 real model requests** were initiated: 1 connection check, 3 contract parses (including one failed BFS parse), and 4 Python generations. Further tests reused the resulting Python and made no model calls. Billing amounts/token usage were not available through the current sanitized app API; consult the provider dashboard. No generated Python was manually edited, run on the host, or replaced by fixture code.

## Reproduction And Artifacts

The added scripts support real tests through an already running service, so a session-only UI key never needs to be exposed or copied. `tests/live-ui.ts` separates parse, manual review and generation; generation requires both paid-call opt-in and explicit contract-review opt-in. `tests/live-ui-browser.ts` imports a real bundle then re-executes unchanged Python through the UI. `tests/live-boundaries.ts`, `tests/live-trace-diagnostic.ts` and `tests/live-trace-audit.ts` make no model calls.

Local artifacts are archived under `artifacts/live-2026-09-22/` (Git-ignored), including original/reviewed contracts, explicit review notes, all generated programs, successful result bundles, failure diagnostics and real browser screenshots. Temporary originals also remain in `test-results/live-ui-*`. No model settings file, authorization header or key is in those artifacts.

Useful local bundles to reopen through the app's **Import Result File** control:

- `artifacts/live-2026-09-22/bfs/bfs-generate-2.bundle.json`: real BFS sample, distance 6; missing obstacle markers remain a known issue.
- `artifacts/live-2026-09-22/dp/dp-generate.bundle.json`: real DP sample, sum 10; incomplete reconstruction animation remains a known issue.

Production application code and the generated Python were not changed in this test turn. Next implementation work should provide the model the complete bounded SDK schema, distinguish return-path coordinates from trace cell IDs, offer field-level sanitized validation errors, and check teaching-state completeness separately from runtime/result correctness. None of those fixes is claimed complete here. Native Windows, other providers/models, full public multi-tenant security and reliable one-shot generation remain unverified.
