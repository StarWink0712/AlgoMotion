- 确认源码、文档、算法实现和测试数据没有来自内部仓库、业务需求、客户资料、内部文档或同事未授权的成果。AI 生成并不会自动解决来源、保密或版权问题。

- 如需审批，保留适当的书面确认，但不要把内部审批内容、员工标识或审批链接提交到公开仓库。本项目不代替法律意见。

## 文件边界

仅以包含 `package.json` 的应用目录中经过审查的源码为发布范围；在完整工作目录中是 `outputs/algomotion/`，单独的应用源码包以解压内容为准。不上传父目录、临时工作目录或旧源码压缩包。`.env`、`.algomotion/`、本地 npm 配置、依赖安装目录、编译产物、运行记录、数据库、私钥、图片、录像和压缩包默认排除。被忽略不代表已跟踪的文件自动从 Git 历史消失。迁移和重新配置见[安装指南](INSTALL.md)。

```sh
npm run release:check
npm run check
npm run build
```

`release:check` 只做本机扫描：核对已知本地密钥是否复制到候选源码、常见凭证形态、当前真实 home 路径、私网 IP、符号链接/未知二进制和锁文件下载来源；如已初始化 Git，也检查被排除文件是否已被跟踪。输出只有文件、规则和行号，不输出匹配原文或密钥。退出码 0 仅表示所检查规则未发现问题，不表示可以发布。

可在 git-ignored 的 `.algomotion/release-audit/terms.json` 中保存需要拦截的内部域名、项目代号等字符串数组；不要把这些关键词写进公开的测试、报告或扫描脚本。扫描器不会联网，也不覆盖 Git 历史、已删除文件、媒体内容、浏览器题库及过往模型请求。未知秘密或业务语义可能不符合任何规则。

发布前还需人工确认 Git 暂存区、提交作者信息、README/issue 附件及任何发布压缩包；提交身份宜使用经本人确认的公开身份或 GitHub noreply 地址。不要直接使用 `git add -f` 绕过排除规则。

## 模型与证据

生成模式会把题目和必要数据发送给用户选择的模型服务。不要输入公司内部题目、业务代码、数据或其他受限信息；遵守公司的 AI 使用政策。当前源码扫描不能证明过去的请求从未包含敏感内容，也无法撤回已发送的信息。

依赖来自公共仓库、自动测试通过或扫描无命中，均不能证明独立创作或法律合规。以人工来源核对和适用的授权流程为最终发布前提。
