# 故障排查

[返回 README](../README.md) · [安装指南](INSTALL.md) · [使用手册](USAGE.md)

排查顺序：Node/npm → 应用目录与依赖 → 网页/API → 容器 → 模型 → 生成内容。不要为排查开启公网访问、关闭安全策略或公开密钥。

## Node 和 npm

### `npm: command not found` / `node` 不是命令

先重新打开终端，检查 `node -v` 和 `npm -v`。macOS/Linux 可用 `command -v node`、`command -v npm` 查看实际路径；Windows CMD 用 `where node`、`where npm`，PowerShell 用 `Get-Command node`、`Get-Command npm`。

如果之前已经安装，可能是当前终端没有加载 PATH 或 Node 版本管理器，不一定需要重装。按所用安装器的说明恢复 shell 初始化。Homebrew 用户先查看 `brew --prefix`；Apple Silicon 常见目录为 `/opt/homebrew`，Intel 常见为 `/usr/local`，不要混用两套安装。

例如确认 Homebrew 在 `/opt/homebrew` 后，下面的命令只为**当前终端**加载路径：

```sh
eval "$(/opt/homebrew/bin/brew shellenv)"
node -v
npm -v
```

要让新终端持续生效，按 Homebrew 的安装完成提示，把对应初始化行放入实际使用的 shell 配置（zsh 通常为 `~/.zprofile`，bash 登录终端通常为 `~/.bash_profile`），避免重复添加。使用版本管理器时遵循其说明，不要同时叠加多套 Node 路径。仍未安装则使用 [Node.js 官方安装包](https://nodejs.org/en/download)。

### 安装时连续出现 `Invalid input. Please press 'y'...`

安装器正在等待确认，不是在执行 shell 命令。此时仅输入 `y` 并回车，等待回到正常提示符后再执行下一步。不要把 `eval`、`node -v` 等后续命令一起粘贴到 `y/n` 提示中。若安装已经退出，重新运行安装命令并逐步操作。

### Windows 提示 `npm.ps1` 禁止执行

不需要放宽系统执行策略。改用 CMD，或在 PowerShell 使用：

```powershell
npm.cmd ci
npm.cmd run dev
```

## 目录、依赖和端口

| 现象 | 检查与处理 |
| --- | --- |
| 找不到 `package.json` / `ENOENT` | 进入包含本项目 `package.json` 的应用目录。完整工作目录通常需先进入 `outputs/algomotion/`。 |
| Node 版本过低、语法/引擎错误 | `node -v` 应至少为 22.12；安装新版本后确认当前终端实际使用的路径。 |
| 缺失模块或跨系统原生依赖错误 | 在目标系统运行 `npm ci`，它会按锁文件重建依赖；不要分享或复用其他平台的 `node_modules`。 |
| 依赖下载失败 | 检查网络、代理和 npm registry，按本机网络政策处理；不要关闭 TLS 校验、公开含令牌的 `.npmrc` 或擅自重写锁文件。 |
| 5173 已占用 | 回到自己先前启动的项目终端停止旧服务，或继续使用它。不要盲目结束其他程序；Vite 使用 strictPort，不自动换端口。 |
| API 3001 已占用 | 确认自己的旧服务，或在 `.env` 同步调整 `PORT` 和 `ALGOMOTION_API_PORT` 为同一个空闲端口，再重启。 |
| 网页能开但 `/api` 返回错误 | 查看启动终端的 API 状态；不要只启动 Vite。确认 API 端口和代理一致。 |
| `npm start` 后无网页 | 先执行 `npm run build`，再启动并访问 API 端口，默认 3001，不是开发端口 5173。 |

## 容器与 `NOT RUN`

缺少 Docker 不影响预设题，但生成程序绝不会改在宿主机运行。先在应用目录运行 `npm run doctor`，根据输出判断引擎和镜像是否就绪。

- **引擎未启动：** 已配置环境可运行 `npm run runtime:start`；macOS 尚未配置专用环境则按安装指南运行 setup。Linux/WSL2 先按官方说明准备可访问的 daemon。
- **没有沙箱镜像：** 引擎启动后执行 `npm run sandbox:build`。仅安装 Docker CLI 不代表有引擎，只有引擎也不代表已构建应用镜像。
- **看得到镜像但应用仍说缺失：** 检查应用使用的引擎。专用 Colima 使用 `colima-algomotion` context，可能不同于终端默认连接；用 `docker --context colima-algomotion images` 检查专用环境，不必改变全局 context。
- **Colima 首次启动失败：** 查看 `colima status algomotion` 和 setup 输出，检查虚拟化、镜像下载及可用磁盘。不要用删除所有 Docker/Colima 数据作为第一步。
- **切换引擎后失败：** 核对 `.env` 的 runtime 与显式 Docker 变量，重启 API，在目标引擎重新构建镜像。显式无效连接不会自动回退。
- **Windows containers：** 需要 Linux 容器引擎，推荐 WSL2；项目不会自动更改系统引擎模式。
- **超时或清理异常：** 先查看具体错误码，取消本应用任务。若系统无法确认容器清理，后续执行会停止；按报错检查对应任务，不要清理所有容器或关闭限制绕过问题。

`test:sandbox` / `test:live` 输出 `NOT RUN` 意味着未满足执行前提，退出码为 2，不是 PASS，也不是 mock 通过。前者需要实际引擎和镜像；后者还需要可用模型配置与 `ALGOMOTION_LIVE_ACCEPT=1` 的明确费用授权。

`doctor` **不读取 UI 持久配置**。只在网页配置 API 时，doctor 可以显示环境变量缺失，但网页仍可使用；反之 doctor 字段齐全也不证明密钥有效。`test:live` 会读取持久化 UI 配置或环境配置，读不到另一个服务进程的临时设置。

## 模型配置与 HTTP 错误

打开“模型设置”先看**当前使用**的配置，确认供应商、地址、模型和高级参数。修改 `.env` 不会覆盖当前 UI 配置，必要时选择“使用环境变量”并重启。

| 错误/现象 | 含义及处理 |
| --- | --- |
| HTTP 401 | 通常是认证被拒绝。核对密钥是否属于这个服务/账号、是否撤销/过期及地址是否正确；不能仅凭 401 断定余额或算法有问题。 |
| HTTP 400 | 请求参数被拒绝。核对模型 ID、Chat Completions 路径、JSON 模式、Token 参数和思考设置；不同模型能力不一致，不能只凭状态码断言是哪个字段。 |
| HTTP 403 / 404 | 可能无模型权限、地区限制或路径/模型不存在；结合供应商文档和控制台排查。 |
| HTTP 429 / 5xx | 可能触发限流、配额或供应商故障。查看供应商状态，等待后手动重试；没有自动付费重试。 |
| 保存后重启失效 | 确认是否选了“临时使用”或启用了 memory 模式，检查文件权限/保存错误；不要公开配置文件内容。 |
| “配置已变化” | 多标签页或其他进程更新了配置。刷新配置后再操作，不强行覆盖。 |
| “已保存”但生成失败 | 保存不调用模型，测试连接也只验证小型请求，不证明长输出、生成能力或算法正确。 |

兼容服务可在高级设置尝试供应商支持的 JSON Object 或仅提示词约束，但应先核对文档，不能通过跳过结构校验解决错误。更换供应商/地址后必须使用对应密钥，应用不把旧密钥悄悄转发给新地址。

## 生成内容失败

| 错误类型 | 下一步 |
| --- | --- |
| `MODEL_CONTRACT_JSON` / `SCHEMA` / `INPUT` | 模型约定格式或样例不合法。根据字段诊断修改约定，或明确重新解析；不要把不合法输出标成成功。 |
| `MODEL_PYTHON_SCHEMA` / `LIMIT` | 模型代码响应不符合协议或超限，可显式重试生成，不能直接绕过校验执行。 |
| `MODEL_TRUNCATED` | 模型输出被截断。核对供应商上限与输出预算，简化任务后再尝试；提高预算也受应用边界限制。 |
| 运行超时、内存/输出/轨迹超限 | 缩小教学输入或显式修复程序。不移除隔离，不直接在宿主机跑生成代码。 |
| 模型样例/独立验证失败 | 查看实际输入、输出及约定差异，核对所选验证器适用性，再修复；能播放不等于算法正确。 |
| `MODEL_PRESENTATION_SCHEMA` / `PRESENTATION_BINDING` | 设计字段、数据绑定或容量不适配。检查诊断与保留的原始执行，可显式重新设计；不要把布局失败描述为全部生成通过。 |
| 追问太多 | 先核对题面是否冲突；普通实现细节由模型采用默认值。旧解析结果不会自动改变，可主动重新解析，仍需审核关键假设。 |

完整错误码与边界见[生成协议](GENERATION.md)。错误信息刻意不返回供应商原始响应、任意异常文本或凭证；公开报告前仍应审查输入、代码、截图和导出文件。

## 题库或任务不见了

先回到原来的浏览器、地址和端口。`localhost` 与 `127.0.0.1`、5173 与 3001 是不同来源，不共享题库。浏览器清理数据、无痕会话关闭可能删除记录，只有已导出的条目才能手动恢复，应用没有云端备份。

关闭新题窗口不取消生成，但刷新页面、离开页面或 API 重启不保证保留未保存任务/草稿。请显式保存到题库。打开导入结果不会执行 Python，旧验证标记显示“未重验”是设计行为，不是丢失验证功能。

## 提交问题前

提供系统/浏览器/Node 版本、操作步骤、错误阶段与错误码、经审查的最小题意/JSON 输入、预期与实际结果。说明是真实模型、真实容器还是 mock 测试，以及是否发生过切换模型/引擎。

不要提交 API Key、`.env`、`.algomotion/`、完整供应商响应、内部链接、原始业务数据或未审查的截图。项目不会根据一张 HTTP 状态码截图推断唯一原因。
